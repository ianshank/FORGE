## 2. Decision D2: Default Branch Rename to `main`

FORGE's development branch has historically been `claude/plan-forge-environment-htAoK`.
To establish `main` as the standard public default branch while preserving git commit SHA history,
commit provenance in benchmark evidence, and automatically retargeting open pull requests:

### Recommended Execution (GitHub API via `gh`)

```bash
# Rename the default branch using GitHub API
gh api --method POST -H "Accept: application/vnd.github+json" \
  "repos/ianshank/FORGE/branches/claude%2Fplan-forge-environment-htAoK/rename" \
  -f new_name=main

# Update local tracking branch
git fetch origin --prune
git branch -m claude/plan-forge-environment-htAoK main
git branch -u origin/main main
git remote set-head origin -a

# Verify open PRs were automatically retargeted to main
gh pr list --base main --state open --limit 50

# Trigger a workflow run on main to publish initial :main container to GHCR
gh workflow run ci.yml --ref main
```

> **Why rename rather than orphan squash?**
> A branch rename automatically migrates branch protection rules, retargets all open PRs,
> and maintains exact commit SHAs referenced in `docs/results/INDEX.toml`, `BENCHMARKS.md`,
> and `CHANGELOG.md`.

## 3. GitHub Pages and Hugging Face Deployment Configuration

Deployments of the browser WebAssembly demo (`web/`) to GitHub Pages and the Hugging Face Space
(`ianshank/forge-wasm-demo`) are currently blocked on operator settings and secrets.

### 3.1 GitHub Pages Enablement
By default, GitHub Pages fails with uninitialized source.
1. Navigate to repository **Settings** → **Pages**.
2. Under **Build and deployment** → **Source**, select **GitHub Actions**.
3. In repository **Settings** → **Environments**, ensure the `github-pages` environment allows deployment from `main`.
4. Trigger the Pages workflow manually or push a commit to `main`:
   ```bash
   gh workflow run gh-pages.yml --ref main
   ```

### 3.2 Hugging Face Token Configuration (`HF_TOKEN`)
The Hugging Face Space synchronization (`.github/workflows/hf-space.yml`) and model publishing
(`scripts/hf_publish_model.py`) fail closed when `HF_TOKEN` is unset.
1. Create a fine-grained or write-scoped API token at `https://huggingface.co/settings/tokens`.
2. Add the token as a repository secret:
   - Repository **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
   - Name: `HF_TOKEN`
   - Value: `<hf_...>`
3. Once provisioned, test synchronization:
   ```bash
   gh workflow run hf-space.yml --ref main
   ```
4. **Note on Model Weights**: Only random-init bootstrap bundles currently exist. Do not publish
   models with `--trained` unless backed by evidential capture records (`evidential_episodes >= 3`).
   `scripts/hf_publish_model.py` defaults to injecting the `UNTRAINED_WARNING` banner into `README.md`.

## 4. Product Fences and Non-Goals
- **Distilled_Agents & Neuroharness**: FORGE is strictly fenced from Distilled_Agents (distillation algorithms) and Neuroharness i2.
- **Cosign & SBOM**: Container signing via Cosign and SBOM generation are deferred post-v0.6.0.
- **Multi-Platform Wheels**: `cibuildwheel` matrices and automated PyPI publishing are deferred post-v0.6.0.
- **Hardware Fault Models**: Autonomous drone vertical is restricted to L0 deterministic process constraints (geofence margins, battery action floors, altitude ceilings converting invalid actions to `Noop`); motor loss and GPS jamming models are non-goals.

## 5. Tagging and Releasing `v0.6.0`

Apply the annotated tag only after the default branch rename is complete, branch protection is configured,
and all CI jobs on `main` are confirmed green.

### Step-by-Step Release Tagging

```bash
# 1. Switch to clean, updated main branch
git checkout main
git pull --ff-only origin main

# 2. Verify all local and CI gates pass
make verify-full

# 3. Create annotated git tag
git tag -a v0.6.0 -m "FORGE v0.6.0 — Unifying the Rust Core, Deterministic Physics, and Ecosystem Compliance"

# 4. Push tag to origin (this triggers Docker release publishing in ci.yml)
git push origin refs/tags/v0.6.0

# 5. Verify CI execution on release tag
gh run list --workflow ci.yml --branch v0.6.0

# 6. Verify published multi-arch container images on GHCR
docker manifest inspect ghcr.io/ianshank/forge:0.6.0
docker manifest inspect ghcr.io/ianshank/forge:latest

# 7. Create GitHub Release
gh release create v0.6.0 --verify-tag --title "FORGE v0.6.0" --notes "FORGE v0.6.0 release baseline hardening."
```
